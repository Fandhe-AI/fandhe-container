# オーケストレーション スコープ

MVP におけるオーケストレーション機能の範囲（CRI-8）と、外部オーケストレータとの境界を定める。

- 決定日: 2026-09-26（ユーザー決定）
- 関連 issue: #20

## MVP スコープ外

- スケジューラ本体（Pod / Node 選定、リソース最適化）
- マルチノード調整（コンテナ配置の重複解消、ネットワークポリシー同期）
- 複数ノード間の状態共有・ハートビート・リーダーエレクション

これらは Kubernetes や他の外部オーケストレータが担当する。本基盤は単一ホストのコンテナ実行に専念する。

## MVP に含む拡張点設計

TASK-4 で定義する 4 つの拡張トレイト（PLUG-1）：

- `ContainerRuntime`: コンテナ起動・シグナル・ライフサイクル
- `NetworkPlugin`: veth / bridge・DNS・ネットワークポリシー
- `VolumeProvider`: ボリューム取付・アンマウント・I/O 最適化
- `StateStore`: コンテナ状態の永続化・読み取り

外部オーケストレータ（Kubernetes 等）とは CRI（`fandhe-container-plugin-cri`）経由で接続する。拡張点の配置は PLUG-1 に従う: `ContainerRuntime`・`NetworkPlugin` の実装は plugin 側（別プロセス＋UDS）、`VolumeProvider` はトレイト・実装とも core 側、`StateStore` はトレイトとファイルベースの既定実装を core に置き、別実装を plugin で差し替えられる。

## 中央常駐デーモンなし

本基盤は中央デーモンを持たない（CORE-1・D-19）。コンテナの監視は supervisor（コンテナごとの軽量プロセス）が担当し、状態管理は StateStore（ファイルベースの既定実装）で行う。複数ノードにまたがる調整は外部オーケストレータに任せ、ホストのリソース消費を最小に保つ（CORE-7〜9）。

## 見直し

MVP 後にマルチノード対応へスコープを拡張する際は、spec（SSOT）で対応するビヘイビア・タスク・マイルストーンを新規定義する。本ドキュメントの更新を経るものとする。
